# Project research

Resolve the original request, canonical project root P, standing goal authority, exact contract/profile and current project state. Keep scientific code, decisions, evidence, feedback and native state in P. Keep package implementation and package qualification in dsh-research.

Treat an outer-loop decision as a change to research methodology. Keep experiment selection, implementation repair, diagnosis and bounded batch exits within the current methodology in the inner loop. Classify a proposed change to observables, measurement approach, representation family or inference contract separately. A checkpoint or new manifest alone does not establish a methodology change. Respect explicit pause and review-only instructions; a skill edit does not update an installed profile or grant execution authority.

The native adapter supports released synthetic development, qualified GPU routes and an explicit project-owned production profile. `NativeProductionResearch` installs on an existing author/Ticket with project proposal/verifier/conclusion hooks and version-four state. Its existence does not qualify a live project profile. Check the applicable deployment/qualification receipt before treating a capability as supported. Keep historical version-three stores pinned until a reviewed supported handoff. Record missing authority, review or native evidence as an owned operational hold; continue unrelated admissible analysis.

## Author procedure

1. Read the exact original request and preserve it verbatim in project artifacts. Reconstruct the current methodology, important blocked decision, accepted evidence, valid negatives, partial lessons and unresolved limitations. Verify that decision-relevant evidence is readable to both author and reviewer; a retained path or hash alone is insufficient. Bind the plan snapshot, candidate/configuration, evaluator/interpreter, released inputs, environment, exact argv/cwd/env, limits and output schema in a frozen manifest. Include relevant dirty/untracked content in the source inventory.
2. Use the configured research_propose tool to freeze the project-supplied proposal, then research_review to obtain completed separate technical review for that exact manifest and proposal. Match the review request, subject, reviewer/profile and consumable scope. An unavailable reviewer holds the dependent action; do not self-approve or substitute a human signature.
3. Invoke only the configured guarded `research_run` tool with immutable manifest/review references and the observed state revision. Never replace argv, invoke another shell path, create a fresh authority or reset consumed attempts/reviews. Leave protected, sealed and confirmation inputs unread under the initial profile.
4. Read the original action association on replay. Treat an unknown launch/settlement as unresolved, retain its reservation, and use existing native ownership/termination evidence for reconciliation. Never repeat an admitted action merely because its worker or transport restarted.
5. Check actual terminal facts, complete captured bytes, identity before/after and the bound domain verifier. Hash and parse the same captured bytes. Preserve interrupted, timed-out, cancelled, truncated or drifted evidence as invalid even when it contains a passing score or exit zero. Keep a valid negative scientifically useful.
6. Read the project checkpoint, retain its scoped findings and compare informative next experiments using [fail-fast and next-experiment guidance](references/fail-fast-and-next-experiments.md). Define the chosen experiment's question, required observables, legal checkpoints and prospective exit conditions before execution. Prepare a bounded successor or return a scoped limitation when no useful inner-loop successor is justified. Continue automatically within standing authority once all prerequisites hold. Preserve earlier failures and charges. Request required human scientific steering only after scoped alternatives, a materially different rebrainstorm and completed separate exhaustion review.

On a production loop, use `research_status` to capture source/reviewer versions and inspect actual costs and scientific discovery. With scientific handoff enabled, its native result exposes exact metadata/catalog roots and a complete retained status reference. Read lesson bodies and catalog pages through `research_context`, supporting evidence through `research_evidence`, and full status through `research_status_read`; preserve explicit paging/completeness and partial-lesson uncertainty before making an inference. Adopt feedback through an unadmitted materially changed proposal with its exact `feedback_item_id` and reason; retain the fresh review and settled effect. Use `research_conclude` for separately reviewed goal completion or scientific exhaustion before a terminal native report. Normal reports use `human_action=null`. Existing Source/startup/scheduled wakeups retain the original author and authority; never restart an admitted action or create an empty replacement record to recover.

Use [packet and outcome guidance](references/packets.md) when preparing references or interpreting a returned association.

## Fail-fast and next-experiment decisions

Read [fail-fast and next-experiment guidance](references/fail-fast-and-next-experiments.md) before defining early exits, comparing alternatives or expanding a measurement matrix. Identify the decision the experiment could change, compare a small evidence-backed slate, and state observable outcome-to-action branches and full marginal costs. Prefer a supported diagnostic or bounded candidate comparison that can remove the current blockage. Treat failure counts and flat scores as reassessment signals; use a qualified prospective stopping rule for a scientific futility claim. Preserve formal confirmation, minimum sampling and matched-repeat obligations.

Read [statistical methods](references/statistics-appendix.md) only when applying a registered futility rule, adaptive racing or an expected-value calculation.

Read [scientific review and partial lessons](references/scientific-review-and-lessons.md) when assembling either party's context or interpreting results. Carry supported prerequisites, valid negatives, tentative explanations and unresolved claims separately into the next checkpoint. Make omissions discoverable and provide complete permitted evidence through an available read-only or preload route. Record missing visibility as a limitation on the affected inference.

## Reviewer procedure

Inspect the exact retained packet and its subject hashes. Return approve/request_changes/defer with matching request, manifest/action and scope, plus reasons and evidence. Preserve actual native reviewer completion bytes. Use the configured restricted reviewer route; a separate Session or prompt alone does not establish filesystem secrecy. Do not launch an experiment or revise shared architecture from this role.

Apply [scientific review and partial lessons](references/scientific-review-and-lessons.md). Reconstruct the blocked decision, test whether the proposed outcomes distinguish the remaining explanations, check controls and stopping rules, and challenge the selected option against the strongest feasible alternative. Give each substantive finding primary evidence, an affected claim and a minimal correction or discriminating experiment. Distinguish missing context from a disproved hypothesis. Keep the required native receipt schema; put the complete evidence-backed critique in its supported reason/evidence fields or a bound permitted artifact. Do not invent new receipt fields.

## Planning and team artifacts

Version accepted deliberate plans/contracts and useful compact conclusions. Retain explorative alternatives/per-attempt detail outside Git under P/local_artifacts/autoresearch/dsh/<goal>/paths/<path>/planning/ and summarize useful findings. Keep large/raw output in project artifacts in either case.

Build a permitted checkpoint release from exact retained bytes, source/config/input references and intended audience. Verify actual content and recipient/asset access before marking publication complete. Keep raw Sessions, secrets and restricted labels out of ordinary releases. A local path or Git clone is not evidence availability; retain supported backups/exports. Publication retries must not cause scientific admission or reset consumption.

Treat feedback as capture → disposition → frozen action change → actual effect → response. Preserve edited source versions and failed/pending effects. A project symptom is a package-maintainer signal; the separate architecture meta-loop review must qualify T1–T4.
