# Project research

Resolve the original request, canonical project root P, standing goal authority, exact contract/profile and current project state. Keep scientific code, decisions, evidence, feedback and native state in P. Keep package implementation and package qualification in dsh-research.

The packaged native adapter currently supports synthetic released CPU development. Its existence does not qualify a live project profile. Check the applicable deployment/qualification receipt before treating a capability as supported. Record missing authority, review or native evidence as an owned operational hold; continue unrelated admissible analysis.

## Author procedure

1. Read the exact original request and preserve it verbatim in project artifacts. Bind the plan snapshot, candidate/configuration, evaluator/interpreter, released inputs, environment, exact argv/cwd/env, limits and output schema in a frozen manifest. Include relevant dirty/untracked content in the source inventory.
2. Obtain completed separate technical review for that exact manifest and proposal. Match the review request, subject, reviewer/profile and consumable scope. An unavailable reviewer holds the dependent action; do not self-approve or substitute a human signature.
3. Invoke only the configured guarded `research_run` tool with immutable manifest/review references and the observed state revision. Never replace argv, invoke another shell path, create a fresh authority or reset consumed attempts/reviews. Leave protected, sealed and confirmation inputs unread under the initial profile.
4. Read the original action association on replay. Treat an unknown launch/settlement as unresolved, retain its reservation, and use existing native ownership/termination evidence for reconciliation. Never repeat an admitted action merely because its worker or transport restarted.
5. Check actual terminal facts, complete captured bytes, identity before/after and the bound domain verifier. Hash and parse the same captured bytes. Preserve interrupted, timed-out, cancelled, truncated or drifted evidence as invalid even when it contains a passing score or exit zero. Keep a valid negative scientifically useful.
6. Read the project checkpoint and prepare a justified bounded successor or diagnostic for fresh separate review. Continue automatically within standing authority once all prerequisites hold. Preserve earlier failures and charges. Request required human scientific steering only after scoped alternatives, a materially different rebrainstorm and completed separate exhaustion review.

Use [packet and outcome guidance](references/packets.md) when preparing references or interpreting a returned association.

## Reviewer procedure

Inspect the exact retained packet and its subject hashes. Return approve/request_changes/defer with matching request, manifest/action and scope, plus reasons and evidence. Preserve actual native reviewer completion bytes. Use the configured restricted reviewer route; a separate Session or prompt alone does not establish filesystem secrecy. Do not launch an experiment or revise shared architecture from this role.

## Planning and team artifacts

Version accepted deliberate plans/contracts and useful compact conclusions. Retain explorative alternatives/per-attempt detail outside Git under P/local_artifacts/autoresearch/dsh/<goal>/paths/<path>/planning/ and summarize useful findings. Keep large/raw output in project artifacts in either case.

Build a permitted checkpoint release from exact retained bytes, source/config/input references and intended audience. Verify actual content and recipient/asset access before marking publication complete. Keep raw Sessions, secrets and restricted labels out of ordinary releases. A local path or Git clone is not evidence availability; retain supported backups/exports. Publication retries must not cause scientific admission or reset consumption.

Treat feedback as capture → disposition → frozen action change → actual effect → response. Preserve edited source versions and failed/pending effects. A project symptom is a package-maintainer signal; the separate architecture meta-loop review must qualify T1–T4.
